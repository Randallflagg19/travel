# First Screen Roadmap

Цель на завтра: довести первый экран Tapir Travel до состояния, которое не стыдно
показать в LinkedIn.

Это не большой редизайн приложения. Это локальный polish первого viewport и
первичной загрузки.

## Контекст

- Tapir Travel — личный travel journal, а не SaaS landing page.
- Проект уже работает: страны, города, фото/видео, upload, delete, likes,
  comments.
- Темная палитра и логотип с тапиром остаются.
- Hero должен выглядеть как осознанный личный продукт frontend-разработчика.
- Первый экран должен вызывать желание пролистать дальше к реальным постам.

## Ограничения

- Не трогать десятки файлов.
- Не менять глобальную архитектуру.
- Не добавлять библиотеки.
- Не превращать страницу в типичный AI-generated landing.
- Сохранять личный характер проекта.
- Проверять desktop и mobile.

## Что сейчас слабое

1. Hero copy слишком общий.

   Текст приятный, но звучит как любой travel journal. Нужно сильнее показать,
   что это личный живой архив и одновременно настоящий frontend-продукт.

2. Фото слишком затемнено.

   Изображение сейчас больше похоже на фон. Для портфолио-экрана фото должно
   доказывать, что проект живой, настоящий и авторский.

3. Первый action недостаточно собран.

   Пользователь понимает, что можно выбрать главу, но hero может лучше вести к
   sidebar/mobile chapters без маркетинговой CTA-кнопки.

4. Cold start должен восприниматься как загрузка архива, а не зависание.

   Loading feedback уже есть, но текст можно сделать менее техническим и более
   связанным с характером проекта.

5. Mobile first viewport может быть слишком тяжелым.

   Нужно проверить, видит ли пользователь не только большой hero, но и начало
   навигации по странам.

## Что видно по текущему скрину

- Первый экран уже не выглядит пустой демкой: есть sidebar, hero, реальные посты,
  counts, upload/delete controls.
- Темная палитра и логотип работают, их не нужно ломать.
- Sidebar с новыми иконками стал заметно лучше и может оставаться как часть
  характера проекта.
- Hero выглядит как затемненный баннер: фото есть, но оно не звучит как главный
  visual proof проекта.
- Текст hero приятный, но слишком безопасный. Он не дает уникального угла:
  почему этот travel journal стоит открыть именно как продукт frontend-разработчика.
- Сетка реальных постов снизу — сильная часть первого впечатления. Hero должен
  вести к ней, а не конкурировать с ней.

## Направления Для Пробы

Перед кодом прогнать 8-10 разных first-screen направлений. Это не финальные
дизайны, а быстрые варианты композиции и настроения.

Кандидаты:

- Cinematic Journal: крупное живое фото, меньше текста, больше воздуха.
- Developer Product: чуть строже, яснее структура `countries -> cities -> media`.
- Field Notes: ощущение дорожного блокнота и личных заметок.
- Gallery First: hero ниже/компактнее, реальные посты видны раньше.
- Route Mood: больше ощущения маршрута без банальной карты.
- Dark Editorial: как обложка независимого журнала.
- Minimal Personal Archive: спокойно, уверенно, почти без пафоса.
- Photo Proof: фото светлее и важнее, текст короче.
- Travel Console: sidebar и hero выглядят как единая система.
- Soft Portfolio: баланс "я разработчик" и "это мой личный проект".

Правило:

- Сначала смотреть варианты глазами.
- Потом выбрать 1-2 направления.
- Только после выбора менять код.

## Файлы-кандидаты

Основные:

- `frontend/src/features/feed/ui/feed-hero.tsx`
- `frontend/src/features/feed/ui/feed-server-loading-notice.tsx`

Возможный третий файл, только если понадобится:

- `frontend/src/features/feed/ui/mobile-chapters.tsx`

Не трогать без отдельной причины:

- backend;
- upload;
- feed orchestration;
- global layout;
- API layer;
- auth.

## Порядок Работы

### 1. Снять текущую картину

- Открыть localhost desktop.
- Открыть mobile viewport.
- Сделать скриншоты текущего первого экрана.
- Проверить, видна ли mobile navigation без лишнего скролла.

### 2. Погонять визуальные направления без кода

- Сделать 8-10 разных вариантов первого экрана.
- Менять композицию, роль фото, плотность текста и связь hero/sidebar/feed.
- Не оценивать сразу по деталям CSS. Сначала выбрать направление.

### 3. Погонять варианты текста отдельно

Цель: сделать текст более личным, точным и не маркетинговым.

Оставить:

- `Tapir Travel`;
- русский характер текста;
- ощущение личного журнала.

Попробовать:

- subtitle вместо слишком общего текста;
- одну сильную фразу про живой архив поездок;
- мягкую подсказку к выбору страны/главы.

Не делать:

- "лучший travel app";
- "AI-powered";
- рекламный hero;
- слишком длинное объяснение.

Тексты, которые точно пересмотреть:

- `личный журнал дороги`;
- `Места, в которых я оказался...`;
- `Коллекционируй моменты.`

### 4. Настроить фото и overlay

Цель: сделать фотографию заметнее, но сохранить читаемость текста.

Проверить:

- затемнение справа;
- градиент между текстом и фото;
- `object-position`;
- не режется ли лицо/важная часть фото на desktop/mobile.

### 5. Улучшить loading notice

Цель: cold start выглядит как нормальная загрузка, а не сломанная страница.

Текущую идею "подключаемся к серверу" заменить на более продуктовую:

- "Открываем архив поездок";
- "Собираем маршрут";
- "Подгружаем главы и первые кадры";
- короткое пояснение, что после паузы первая загрузка может занять дольше.

### 6. Проверить mobile

- Hero не должен съедать весь первый экран без намека на navigation.
- Mobile chapters должны быть видны или хотя бы начинаться сразу после hero.
- Текст не должен ломаться и вылезать.

### 7. Проверки

```bash
cd /Users/tapir/Programming/travel/frontend
npx tsc --noEmit
npm run lint
npm run build
```

Ручная проверка:

- desktop localhost;
- mobile viewport;
- initial load;
- Thailand -> Bangkok/Pattaya;
- Indonesia/Bali;
- all posts.

## Критерии Готовности

- Первый экран выглядит законченным.
- Фото читается как важная часть hero, а не как темная подложка.
- Текст звучит лично и уверенно.
- Пользователь понимает, что можно выбрать страну/главу и смотреть реальные
  посты.
- При cold start понятно, что данные загружаются.
- Изменения локальные и не ломают существующие flow.
